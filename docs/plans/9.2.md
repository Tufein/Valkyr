# 9.2 groundwork — more from RetroAchievements, manuals from the web

Work done on branch `feature/ra-best-games-and-web-manuals`. No version bump: this is groundwork,
not a release. All pure rules have JVM tests, the seven string files are in parity, and
`assembleDebug` plus `compileDebugAndroidTestKotlin` are green.

## 1. Best games per console: more of everything

- **More consoles.** `util/BestGames.kt` (`RaConsoleMap`) maps 35 more RA system ids, using the
  ids from RA's own `RA_Consoles.h` (MS-DOS, Arcade, C64, ZX Spectrum, Amiga, PC-88/98, X68000,
  Game & Watch, N-Gage, Arduboy, TI-83, Uzebox…). Look-alikes such as Jaguar CD and the Famicom
  Disk System stay unmapped, as before.
- **More games.** The candidate list goes from 40 to 100 and the per-console cache from 200 to
  500 games. The throttled details pass is unchanged at one call per game, 1.5 s apart.
- **More facts, no extra calls.** `API_GetGameExtended` already returns hardcore player counts,
  release date and genre; `parseDetails` reads them from the very call that fetched the player
  count. `API_GetGameList` also supplies leaderboard counts. The cache format gained optional keys
  (`h`, `r`, `g`, `l`) and still reads old files.
- **A fairer basis.** `RankBasis.HARDCORE` ranks by hardcore players when every candidate has a
  count, otherwise the screen falls back to points and says so.
- **More control in the list.** Local sort (rank, title, year, points, players) and an ownership
  filter (all / on device / in a source / missing) cost no requests; the earned rank number is
  kept. Rows now show achievements, leaderboards, release year, genre and hardcore players.

Files: `util/BestGames.kt`, `data/service/BestGamesService.kt`,
`ui/screens/tools/BestGamesViewModel.kt`, `ui/screens/tools/BestGamesScreen.kt`,
`res/values*/strings_v92_best.xml`, tests in `BestGamesTest` and `RaConsoleMapTest`.

## 2. Manuals: as many sources as the code can legitimately use

- **RomM** (as before), **ScreenScraper**'s `manual` media type, and the **Internet Archive**'s
  public search and metadata APIs are asked in that order; a **pasted link** is a fourth, explicit
  way in. Each provider has a switch in Settings → Library → Advanced.
- **Honest limits:** a definite miss is remembered for a month and not asked again; a rate limit,
  quota, refused login or offline source is *not* a miss. ScreenScraper credential handling and
  its daily gate are reused unchanged, and credentials are stripped from stored URLs. Archive
  lookups ask for at most two items and one PDF each. The UI says which sources were asked when
  nothing turns up, and every stored manual shows its provider.
- **Safety unchanged:** `.part` writes, never replacing an existing file, one download at a time,
  the total size cap with oldest-first eviction, safe folder names, and https-only redirects that
  stay on the provider's own host. The link dialog rejects local and scripted addresses.

Files: new `util/ManualSources.kt`, `util/ScreenScraper.kt` (`pickManual`),
`data/service/ManualService.kt`, `data/local/ManualSettings.kt`,
`ui/screens/manuals/{ManualsViewModel,ManualsSection}.kt`, settings rows in
`SettingsCardsInterface.kt`, `SearchIndex`/`SettingsLayout`, `res/values*/strings_v77_metadata.xml`,
tests in `ManualSourcesTest`.
