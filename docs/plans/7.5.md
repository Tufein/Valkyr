# 7.5 — more places to keep your data: task list

Backups and device sync today speak WebDAV (or RomM). A NAS that only offers SMB or SFTP, or a
bucket, is out of reach. Paths are relative to `app/src/main/java/com/tufein/valkyr/`.

The one thing that makes this cheap: **everything cloud-side already talks to a single interface**.

- `util/DavStore.kt` (L14–65): `propfind`, `list`, `exists`, `get(url, maxBytes)`, `put`,
  `ensureCollection`, `move`, `delete`, with optional `putStream` / `getStream` (L50) and
  `moveNoReplace` (L61). Backup (`util/CloudBackupEngine.kt`), device sync
  (`data/service/DeviceSyncService.kt`), the shared wishlist (`util/SharedWishlistEngine.kt`) and
  whole-game transfer (`data/service/GameTransferService.kt`, which uses `putStream` at L437,
  `getStream` at L453 and `moveNoReplace` at L395) all run on it. `WebDavClient` is the only
  production implementation; `FakeDavStore` (`app/src/test/java/com/tufein/valkyr/util/CloudFakes.kt`)
  is the test one.
- Address discovery is WebDAV-shaped: `util/WebDavPaths.candidates()` (L181–204) tries the
  Nextcloud/ownCloud forms, and `data/service/CloudConnection.test()` (L41) probes those, makes a
  collection and writes a `.dogmatix-write-test` file.
- Problems are already protocol-neutral in spirit: `util/WebDavStatus.kt` `DavProblem` (AUTH,
  NOT_WEBDAV, PRECONDITION, TOO_LARGE, NO_SPACE, LOCKED, …), `util/CloudErrors.kt` stores them as
  codes, `data/service/CloudMessages.kt` turns them into a sentence.
- Conditional writes exist: `util/DavConditionalWriter.kt` (If-Match / If-None-Match with a
  read-before and read-back fallback for servers without ETags, `MAX_ATTEMPTS = 6`).
- Settings are one flat bundle: `dav_server`, `dav_user`, `dav_password`, `dav_folder`, certificate
  trust (`util/CloudSettingKeys.kt` L19–20, `data/local/CloudSettings.kt`), records in a separate
  DataStore (`dav_device`) so the app password never rides in a backup.
- Encryption is independent of the transport: `util/BackupCrypto.kt` (`DGXB1`, AES-256-GCM,
  PBKDF2 600,000, gzip, 32 MB plain cap). Names and rotation in `util/CloudBackupNames.kt`
  (`toDelete` L119 rolls **only this device's own** backups).
- Scheduling: `data/service/AutoBackupScheduler.kt` — local job 4231 weekly, cloud job 4232 daily
  on charging + unmetered, `runCloud` chaining backup → device sync → shared wishlist. There is no
  retry or backoff anywhere in this path; transient failures are only *silenced*
  (`CloudErrors.isTransient`).
- Dependencies: no SMB, SSH or S3 library is present (`gradle/libs.versions.toml` says so), no
  WorkManager either — planning is `android.app.job.JobScheduler`. OkHttp arrives transitively via
  Coil and is imported directly by `WebDavClient` and friends; that should be declared once this
  area grows.

## 1. Make the store a chosen target, not an assumed one

**Why.** Three new protocols must not each grow their own backup logic.

**What.** A `CloudTarget` (kind + host/bucket/prefix + user/key + trust) replacing the flat
`dav_*` bundle, with `CloudConnection.open()` returning a `DavStore` for the chosen kind. Existing
WebDAV settings migrate to `kind = WEBDAV` on first start, keeping the same stored values.

**Files.** `data/local/CloudSettings.kt`, `util/CloudSettingKeys.kt`,
`data/service/CloudConnection.kt`, `util/WebDavPaths.kt` (candidates only for the WebDAV kind),
new `app/src/test/java/com/tufein/valkyr/util/CloudTargetTest.kt`, plus `SettingSchema` so the new
keys travel in backups without the password.

**Done when.** `CloudBackupEngineTest` and `DeviceSyncEngineTest` still pass against
`FakeDavStore` — unchanged, because nothing above the interface knows the transport — and a
saved WebDAV configuration from 7.4 restores as the same target.

## 2. Three new stores behind the same interface

**Why.** The interface is the whole contract; each protocol is one class.

**What.** `data/service/SmbClient.kt`, `SftpClient.kt`, `S3Client.kt`, each `: DavStore`, each with
`putStream`/`getStream`/`moveNoReplace` implemented for real (game transfer needs them) and `get()`
returning no ETag where the protocol has none — the conditional writer already falls back to
read-before and read-back. S3 lists with a prefix, uses multipart above the single-PUT limit and
reads the server-side checksum where it exists. SFTP walks one directory tree, does no discovery.
SMB speaks to an address the user types; it does not scan the network — that keeps the permission
story small and matches `data/service/WifiReceiveService.kt`, which likewise only listens.

**Files.** new `data/service/SmbClient.kt`, `data/service/SftpClient.kt`, `data/service/S3Client.kt`,
`gradle/libs.versions.toml` + `app/build.gradle.kts` (a pure-JVM SMB client, an SSH client, and
either a hand-written S3 signer or the minimal SDK; OkHttp declared explicitly),
`util/ServerUrlGuard.kt` and `util/CertTrust.kt` for the trust rules, new
`app/src/main/res/values/strings_v75_cloud.xml` plus the six locale copies.

**Done when.** One contract test suite (`DavStoreContractTest`) runs the same assertions against
each implementation and `FakeDavStore`: listing, create collection, write, write-no-replace,
rename, read back with checksum, quota and permission errors mapped to `DavProblem`. A backup
written over SFTP restores byte for byte over SMB.

## 3. One Cloud hub that shows every target

**Why.** `ui/screens/cloud/CloudScreen.kt` shows one WebDAV connection pill (L370) next to RomM,
saves and device sync; with three targets that is no longer enough.

**What.** A list of targets, each with its last run, its result in one sentence and a *Back up
now* that covers all of them; a failure on one target never blocks the others. The connection test
button moves to the target rows (the working code is `CloudBackupScreen.kt` L251–255 and
`CloudBackupViewModel.testConnection` L192–207).

**Files.** `ui/screens/cloud/CloudScreen.kt`, `CloudViewModel.kt`, `CloudBackupScreen.kt`,
`CloudBackupViewModel.kt`, `ui/screens/cloud/DavRows.kt`, `data/service/CloudStatusService.kt`
(`attach(id, flow)` L96 already allows one icon fed by several parts), `util/CloudStatusModel.kt`,
`util/CloudAttention.kt`, `data/service/DavStatusService.kt`.

**Done when.** Two targets configured, one with a wrong password: the hub says which one failed and
why in plain words, the other still backs up, and the status icon explains itself.

## 4. Retries that back off, and a policy that never deletes remotely

**Why.** Today a failed daily run simply waits for tomorrow, and rotation deletes files.

**What.** A small `CloudRetryPolicy` (attempts, exponential wait, never retry a
`FINAL` problem, stop when the battery or network says no — the pattern in `ScanFailures` and
`CoverApiGate` is already in the app), applied to the daily chain. Rotation gains an explicit
switch: keep everything, or delete only this device's own older files (which is what
`CloudBackupNames.toDelete` does today) — and for new target kinds, deleting is off by default.
Verification after a restore is by checksum before anything local is replaced.

**Files.** `util/CloudBackupEngine.kt` (upload, `toDelete` call L105), `util/CloudBackupNames.kt`,
`data/service/CloudBackupService.kt`, `data/service/AutoBackupScheduler.kt` +
`AutoBackupJobService`, new `util/CloudRetryPolicy.kt`, `util/WebDavStatus.kt` (the `FINAL` set),
`data/local/CloudSettings.kt` (the switch), extended `AutoBackupTest` and `CloudBackupEngineTest`.

**Done when.** A target that is briefly unreachable is retried within the same window instead of
the next day, a permanent problem is not retried, and with "never delete" on, a full rotation
period leaves every remote file in place.

## Order of work

1 before 2 (targets, then implementations), 3 and 4 after both. Ticket 2 is three separate PRs:
SFTP first (simplest and most useful for a NAS), then SMB, then S3.

## Where this runs

`FakeDavStore` covers the logic; the contract tests need a real server each — an SFTP server and a
Samba share are easy to raise, and an S3 endpoint can be MinIO. Device checks: a backup to a NAS
over SMB, restored on a second handheld, and a hub that names the one target that failed.
