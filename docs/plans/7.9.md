# 7.9 — series and discovery: task list

Group by series, explain every suggestion, and find the rest of a franchise — without folding
anything the user did not ask to fold. Paths are relative to `app/src/main/java/com/tufein/valkyr/`.

What exists to build on:

- Version folding, the proven pattern: `util/VariantGroups.kt` — `GROUP_KEY = "var60_group"` (L22),
  `DEFAULT_ON = false` (L31), `key()` (L37) on console + `searchKey` + disc part, `group()` (L52)
  on the loaded page. It is applied in `ui/screens/home/HomeViewModel.kt` `listingOf()` (L617) and
  switched in the filter row (`ui/screens/home/HomeScreen.kt` L450–460, strings `var60_*` in
  `app/src/main/res/values/strings_v60_variants.xml`). The flow comes from
  `data/local/LibrarySettings.kt` (L69).
- Scoring and best-version choice are separate and stay untouched: `util/VersionCompare.kt`,
  `util/VersionPicker.kt`, `util/VersionPreference.kt`.
- Series today is only a title heuristic: `util/SimilarGames.kt` — `seriesWords()` (L21) drops
  filler and roman digits, `familyQuery()` (L32) takes the first two words, `score()` (L35) and
  `rank()` (L60) return candidates **without a reason**. The section is
  `ui/screens/home/components/SimilarSection.kt` (`disc6_similar_title`) built by
  `ui/screens/home/GameDetailsLoader.kt` `similarTo()` (L107).
- Suggestions do explain themselves, and that is the model to copy: `util/ForYou.kt`
  `ReasonKind { SERIES, BECAUSE, POPULAR, GENRE, DECADE, FEW_ON_CONSOLE }` (L27), `seriesKey()`
  (L93), `MAX_PER_SERIES = 3` (L71), `shown(reasons, max = 2)` (L315); the UI line is
  `ui/screens/next/UpNextScreen.kt` `reasonText()` (L372) with `next30_why_series` = "Same series
  as …". Seeds come from `data/service/ForYouService.kt`.
- No series field exists anywhere: `data/local/entity/GameMetadataEntity.kt` has title,
  description, genres, released, developer, imageUrl, source, fetchedAt — nothing about series,
  and `util/Igdb.kt` never asks for `collections`/franchise (its body asks for
  `name,cover.image_id,platforms`).
- Search runs on `searchKey`/`searchWords` with the FTS table added in `Migration15To16`
  (`data/local/queries/LibraryQueryBuilder.kt` L13, L192), so a series that is only a runtime
  heuristic cannot be searched.

## 1. "More like this" says why, per card

**Why.** The reason model already exists for suggestions; similar games show none.

**What.** `SimilarGames.rank` returns candidates with a small reason list — same series, same
developer, shared genre, same console — reusing `ForYou.Reason`'s shape, and `SimilarSection`
shows one reason line per card. Pure logic first, UI after.

**Files.** `util/SimilarGames.kt`, `util/ForYou.kt` (shared reason type),
`ui/screens/home/GameDetailsLoader.kt`, `ui/screens/home/components/SimilarSection.kt`,
`ui/screens/game/GamePage.kt` (the tab), new `strings_v79_series.xml` keys `disc79_why_*` in the
seven language files, extended `SimilarGamesTest`.

**Done when.** Every suggestion in the section carries one reason, and `SimilarGamesTest` pins the
weights so a card cannot appear without one.

## 2. A series key that can be stored and searched

**Why.** Series grouping and series search both need the same fact, and today it is recomputed
from a title string.

**What.** A pure `util/SeriesKey.kt` (`key(consoleId, title, searchKey)` from the words
`SimilarGames.seriesWords` already produces, with the filler list as data), and a place to keep
it: a `series` column on `game_metadata` filled by a new `Migration16To17` written like
`Migration15To16.kt` (pure `plan()` + test), backfilled for rows that already have genres, and
refreshed when metadata is fetched.

**Files.** new `util/SeriesKey.kt`, `data/local/entity/GameMetadataEntity.kt`,
`data/local/DogmatixDatabase.kt` (version 16 → 17) + new `data/local/Migration16To17.kt`,
`di/DatabaseModule.kt` (registration), `data/service/GameMetadataService.kt`, new
`SeriesKeyTest.kt`, `Migration16To17Test.kt` (and an instrumented migration test next to
`DatabaseMigration16RegressionTest`).

**Done when.** The key is stable across regions and revisions ("Mega Man X (USA)", "Rockman X"
aside — the aliases question is ticket 4), and the migration is tested without a device.

## 3. Series view as an option above version grouping

**Why.** A shelf per series is what "grouped" means to a person; regional copies must stay folded
inside one entry, not become a separate series row.

**What.** `util/SeriesGroups.kt` folding **after** `VariantGroups.group` in `listingOf()`, with its
own key `var79_series` registered next to `GROUP_KEY` in `SettingSchema`, off by default, and a
visible "what did I just fold" list with one tap to undo. No file ever moves; the switch is a view
setting only, so it travels in backups as a setting and changes nothing on disk.

**Files.** new `util/SeriesGroups.kt`, `ui/screens/home/HomeViewModel.kt` (L617 area),
`ui/screens/home/HomeScreen.kt` (filter row), `data/local/LibrarySettings.kt`,
`util/VariantGroups.kt`, `util/SettingSchema.kt`, `ui/screens/home/ShelvesModel.kt` (a series
shelf), new `SeriesGroupsTest.kt`.

**Done when.** Turning it on groups by series without hiding region variants, turning it off
returns the previous list exactly, and `SeriesGroupsTest` covers both plus the "nothing folded"
case.

## 4. Search that finds a series when titles differ

**Why.** Substring or FTS search cannot connect *Super Mario Kart* to *Mario Kart 8*.

**What.** Use the stored series key as a search facet: `LibraryQueryBuilder` accepts a
series-scoped query, the suggestion cards and the series shelf carry a *search within this series*
action that sets that facet (the same route as `data/state/PendingLibraryFilters.kt`, and a deep
link so a launcher shortcut can open it), and the aliases for known franchise name changes live as
data in `util/SeriesKey.kt`, not in code branches.

**Files.** `data/local/queries/LibraryQueryBuilder.kt`, `util/SearchNormalizer.kt`,
`data/state/PendingLibraryFilters.kt`, `util/DeepLinkParser.kt`, `ui/screens/search/SearchAllScreen.kt`,
`util/SeriesKey.kt`, extended `LibraryQueryBuilderTest`.

**Done when.** One tap on a Mario card lists the Mario games on the console, including titles that
do not contain the word "Mario", with the reason line still visible.

## Order of work

1 is a day of work and makes the promise ("always says why") true everywhere. 2 is the schema step
everything else needs. 3 is the visible feature. 4 is the payoff.

## Where this runs

1, 2 and 3 are pure and unit-tested; the migration is tested like `Migration15To16Test`. 4 needs a
look on a device: the facet must survive rotation and a profile switch, and `SearchIndexTest` keeps
"search everything" honest.
