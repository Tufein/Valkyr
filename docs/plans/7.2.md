# 7.2 — task list

The 7.x pass finished most of what this milestone set out to do. What is left is a short,
checkable list; each ticket can go into the issue tracker as written. Paths are relative to
`app/src/main/java/com/tufein/valkyr/` unless they start with `docs/`.

Already in place (7.2.0, build 80):

- The five READMEs name 7.2.0 and build 80, guarded by `ReleaseDocsTest`.
- All 4,222 translatable resources exist in the seven languages, guarded by
  `StringResourceParityTest`. Six technical entries (HTTP and MIME constants, the font-provider
  certificates) are now `translatable="false"`, and the copies of the HTTP and MIME constants that
  sat in five locale files are gone, so every language carries the same set.
- 18 of the 20 `*Dialog.kt` files scroll their content; the two exceptions are `ConfirmDialog`
  (one question and two buttons) and `DialogKeys` (not a screen).

## 1. Landscape audit of the screens behind the dialogs

**Why.** 7.1 made the dialogs scroll on a ~400 dp high landscape screen, but the screens a
dialog opens were not part of that pass.

**What.** On a device or emulator at 400 dp height with font size at 200 %, open each area and
check: the last action is reachable, nothing is clipped, the D-pad focus follows a scrolled
container, and a rotation keeps the place.

| Area | Files to look at |
| --- | --- |
| Home and its cards | `ui/screens/home/` |
| Library, covers, versions | `ui/screens/game/GamePage.kt`, `ui/screens/home/Shelves.kt` |
| Downloads and its queue controls | `ui/screens/download/` |
| Sources, catalogue, RomM pairing | `ui/screens/sources/` |
| Tools (60 files) | `ui/screens/tools/`, especially `RecapScreen.kt`, `BestGamesScreen.kt`, `HistoryScreen.kt` |
| Settings (20 files) | `ui/screens/settings/` |
| Onboarding, tour, what's new | `ui/screens/onboarding/`, `util/AppTour.kt`, `ui/components/TourDialog.kt` |
| Manuals and the reader | `ui/screens/manuals/` |
| Search, search everything, share | `ui/screens/search/`, `ui/screens/share/` |
| Second screen | `ui/secondscreen/` |

**How to fix.** Wrap the scrolling area in `Modifier.verticalScroll(rememberScrollState())` and
keep the buttons outside it, as `GameDetailsDialog` does; move focus with
`BringIntoViewRequester` when the focused row leaves the viewport.

**Done when.** The table above passes at 400 dp / 200 % text, on a phone in landscape and on the
Thor, with a controller.

## 2. Empty-state audit

**Why.** An empty screen that only says "nothing here" reads as a fault; it should say what the
screen is for and offer the one action that fills it.

**What.** 31 call sites already use the shared `EmptyState` in `ui/components/Kit.kt`. Check the
areas that do not: `ui/screens/cloud/`, `ui/screens/manuals/`, `ui/screens/more/`,
`ui/screens/offline/`, `ui/screens/onboarding/`, `ui/screens/settings/`, `ui/screens/share/`,
`ui/screens/contact/`.

**Rules.** One sentence in plain language, one action, no exclamation marks; say which folder,
server or setting is missing when that is the reason.

**Done when.** Every screen reachable with an empty library, no source and no RomM server says
what it is for and what to do next.

## 3. Destructive-path test gate

**Why.** Anything that deletes, moves or replaces has to keep its preview and its way back.
Today that is enforced by convention and by review, not by a failing test.

**Already covered.** `util/RecoverySafetyTest.kt` (verified copies, interrupted transfers,
save/state exclusion), `util/RecoveryScopeTest.kt`, `util/LibraryMoveTest.kt`,
`util/PlaylistMovePathsTest.kt`, `util/ActionHistoryTest.kt`, `util/GameJournalTest.kt`.

**To add.**

1. `TrashService` — a restore puts the file back with its original name, a second restore of the
   same entry is refused, and an expiry never removes a file that was already restored.
2. `RecoveryHubService` — a replacement is only offered when the recovered copy verifies; a
   folder that changed since the copy is reported, not silently overwritten.
3. `ActionUndoService` — undo of a delete goes through Trash, and an undo that cannot verify its
   copy leaves the history entry in place.

**Done when.** Each new test fails if the verification step or the Trash step is removed.
