# 9.0 — one evening, one handheld: task list

The first release under the rule in [ROADMAP.md](../ROADMAP.md#what-counts-as-a-release): a theme,
three to five visible features, two real devices, a few days of soak, and nothing half-done.
Paths are relative to `app/src/main/java/com/tufein/valkyr/`.

What already exists to build on:

- **Setup, but per screen**: `util/EmulatorSetupPlan.kt` (7.4) turns a console's gap into steps,
  `data/service/GameReadinessService.kt` verifies one game, `data/service/BiosService.kt` checks
  the BIOS folder, `util/NewHandheldPlan.kt` opens the right screen per step.
- **Cloud restore, but on its own screen**: `data/service/CloudBackupService.kt`
  (`prepareRestore`, `restore`) over `util/CloudBackupEngine.kt` and the `DavStore` interface
  (WebDAV since 7.5, S3 since 8.2).
- **Progress, but no time**: `util/GameProgress.kt` (8.3) holds a play status and a rating per
  profile, synced as `progress_<profile>.json`; `data/service/RecapService.kt` and `YearRecap`
  build a recap from what little is recorded.
- **Cheats do not exist**: one comment in `util/EmulatorSaveLayouts.kt`; RetroAchievements does
  know about hardcore (`util/RaApi.kt`, `util/RaStatus.kt`), and the app cannot yet say "no" for
  the right reason.
- **Metadata is chosen, never corrected**: `util/CoverSources.kt` orders providers and
  `data/service/CoverRepository.kt` caches a cover per `console|stem`, with no per-game override.
- **Accessibility is one line in the roadmap**: TalkBack labels exist on 65 files, no font-scale
  audit, and `ui/theme/ConsoleColors.kt` was chosen for looks, not for colour blindness.

## 1. One flow from install to first game

**Why.** Seven screens answer seven questions and none of them says "you are done".

**What.** `util/NewDeviceFlow.kt`, pure: from the backup target, the installed packages, the
BIOS report and a sample of the library, produce an ordered list of steps — *restore*, *folders*,
*emulators*, *BIOS*, *library sample*, *first launch* — each with what it will write and the
check that proves it. A screen walks it, each step opens the existing screen, and the last page
lists what is ready and what still blocks, with the one tap that fixes it. Closing the app keeps
finished steps.

**Files.** new `util/NewDeviceFlow.kt`, new `ui/screens/tools/NewDeviceFlowScreen.kt` +
`NewDeviceFlowViewModel.kt`, `data/service/CloudBackupService.kt`,
`data/service/GameReadinessService.kt`, `util/EmulatorSetupPlan.kt`, `util/NewHandheldPlan.kt`
(feed it the flow's state so it stops pointing at finished screens), `ui/navigation/NavRoutes.kt`,
`MainActivity.kt`, `ui/screens/tools/ToolsHubScreen.kt`, `util/SearchIndex.kt`, new
`app/src/main/res/values/strings_v90_flow.xml` plus the six locale copies.

**Done when.** `NewDeviceFlowTest` covers: empty device, backup present but a wrong password,
BIOS missing for one console, and a library that is complete — and the flow never claims a step
passes without running its check.

## 2. Time played

**Why.** The app knows *that* you played (ES-DE's `playcount`/`lastplayed`, RomM saves) but never
*how long*, so the recap and *Continue playing* say almost nothing.

**What.** Sessions measured around `GameLaunchService.launch()` and the app returning to the
foreground: start, stop, length, per game and per profile. Totals feed the game page (time
played, sessions, first and last played) and `RecapService` (this week, this year). A clock that
jumps backwards is clamped the way `PlayHistory` already does it; a crash mid-session loses at
most the running session and never double-counts.

**Files.** new `util/PlaySessions.kt` (pure: merge, clamp, totals), new
`data/service/PlaySessionService.kt`, `data/service/GameLaunchService.kt`,
`MainActivity.kt` / `DogmatixApplication.kt` (foreground and trim events),
`data/service/RecapService.kt`, `util/YearRecap.kt`,
`ui/screens/game/GamePage.kt`, `ui/screens/tools/RecapScreen.kt`,
`ui/screens/home/ShelvesModel.kt` (*Continue playing* uses it), `strings_v90_playtime.xml` ×7.

**Done when.** `PlaySessionsTest` covers clamp, crash, pause, profile switch and two sessions in
one day; a week of use fills the recap; and the screen says in its own words that a device left
running counts until the screen turns off.

## 3. Cheats, honestly

**Why.** There is no cheat support at all, while RetroArch reads `.cht` and hardcore mode forbids
both cheats and save states.

**What.** Import a `.cht` per game from the file explorer or a share sheet, keep it with the game
(a `cheats/` folder the user grants for RetroArch's own discovery, nothing written into another
app's private files), list it per game with an on/off switch, and refuse it — with a sentence and
a way out — while achievements run in hardcore. Standalone emulators only where their own
documented format is known, the rest say so instead of pretending.

**Files.** new `util/Cheats.kt` (pure: parse, name, match to a game, hardcore verdict), new
`data/service/CheatService.kt`, `data/service/GameLaunchService.kt`, `util/RaStatus.kt`
(hardcore state), `ui/screens/game/GamePage.kt`, `ui/screens/tools/FileExplorerScreen.kt`
(import), `ui/screens/settings/` (where cheats live), `strings_v90_cheats.xml` ×7.

**Done when.** `CheatsTest` covers import, a file for another game, a broken file and the
hardcore refusal; and nothing is ever downloaded from a cheat site.

## 4. Fix the match

**Why.** A wrong cover or year cannot be corrected by hand; only the provider order can change.

**What.** A per-game override for title, year, genre and cover, keyed `console|stem` like
`covers` so a rescan keeps it; a pinned cover that stays above the provider chain; one tap back
to automatic per field; overrides carried in backups and never overwriting a field that was left
automatic.

**Files.** new `data/local/entity/GameOverrideEntity.kt` + DAO, `data/local/DogmatixDatabase.kt`
(version 16 → 17) with a new `Migration16To17.kt` in the shape of `Migration15To16.kt` (pure
`plan()`, unit test), `di/DatabaseModule.kt` registration, `data/service/GameMetadataService.kt`,
`data/service/CoverRepository.kt` (`util/CoverSources.kt` pin), `ui/screens/game/GamePage.kt`,
`ui/screens/home/components/GameDetailsDialog.kt`, `data/service/BackupService.kt` +
`util/BackupJson.kt` (a section, versioned), `strings_v90_overrides.xml` ×7.

**Done when.** `Migration16To17Test` proves the migration without a device, and a corrected game
survives a rescan, a backup and a restore, then returns to automatic in one tap.

## 5. Readable for everyone

**Why.** The app is dense, every screen was designed at default text size, and TalkBack gets
little help.

**What.** One sentence per cover and tile (title, console, size, state) instead of "image";
200% text that reflows the 400 dp screens, the Tools graphs and the game page; a colour-blind-safe
palette in `ConsoleColors` where colour is never the only cue; a reduce-motion switch and larger
touch targets; an accessibility line in Health, and a large-text cover grid measured by the
Performance check rather than assumed.

**Files.** `ui/components/CoverImage.kt`, `CoverCard.kt`, `ui/screens/home/LibraryBrowseUi.kt`,
`ui/screens/home/Shelves.kt`, `ui/theme/ConsoleColors.kt`, `ui/theme/Theme.kt`,
`data/local/SettingsDataStore.kt` (reduce motion), `ui/screens/settings/`,
`util/HealthRules.kt` + `data/service/HealthService.kt`, `util/PerfCheck.kt` +
`data/service/PerfCheckService.kt`, `strings_v90_a11y.xml` ×7.

**Done when.** TalkBack walks library → game → back without a dead end, 200% text clips nothing
on the 400 dp screens, and the palette has a contrast check with the numbers written down.

## Order of work

1 and 2 carry the release; 3 and 4 are the two things people ask for by name; 5 is the one that
must not be squeezed at the end, so it starts in parallel with 1. The release is not tagged until
the rule's two devices and the soak are done — that is the point of the rule.

## Where this runs

1, 2 and 4 are unit-testable (the migration especially). 3 needs RetroArch and its cheat folder
on a real device, and 5 needs TalkBack turned on, which no test replaces. Everything here is
judged on a phone and a handheld, in landscape, with buttons.
