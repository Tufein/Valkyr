# 7.8 — catalogue and sources: task list

More optional content, better visibility into what a source actually does, and an arcade console
that is honest about what it offers. Paths are relative to `app/src/main/java/com/tufein/valkyr/`.

How the catalogue works today:

- `app/src/main/assets/romsets.json` (schema 2) lists providers and entries — 29 Libretro systems,
  one ScummVM entry with nine folders, two Homebrew Hub entries: 32 entries, 317 files counted for
  Libretro. Those numbers are asserted in `app/src/test/java/com/tufein/valkyr/util/RomsetCatalogTest.kt`
  (L53–71), so adding an entry means updating that test on purpose.
- The trust decision is code, not data: `util/RomsetCatalog.kt` `TRUSTED` (L56–60) with base
  address, provenance and `Kind` (L45–50), `Licence` (L33–42: PUBLISHED, PUBLIC_DOMAIN,
  FREE_LICENCE), `parse()` (L106–143) rejecting an unknown provider, a moved base URL or a
  duplicate address, and the caps `MAX_PROVIDERS = 16`, `MAX_ENTRIES = 256`, `MAX_PER_PROVIDER = 64`,
  `MAX_FOLDERS = 16`.
- Homebrew Hub is read by `util/HomebrewHub.kt`, fixed to GB/GBC (`Platform` L43, `BASE_PATH =
  "database-gb"` L30, `romExtensions` L175) with a licence whitelist (`licenceOf` L146–171) and
  page caps. Another system means a new platform, base path and extensions.
- Scanning reuses the normal path: `data/service/DatabaseScrapingService.kt` routes magnet/torrent,
  `romm://`, Homebrew Hub (L204–235) and HTTP listings (L125–140), and `util/ListingCheck.kt`
  (`PARSER_VERSION = 2`) decides what can be skipped. Catalogue sources are added as `UrlEntry`s
  **without mirrors** (`data/repository/SourcesRepository.kt` `mergeRomsets()` L83–115), even
  though the download side already supports them (`util/MirrorUrls.kt`,
  `data/service/DownloadServiceTransfers.kt` L368–416).
- Attribution lives in the browser dialog: `ui/screens/sources/RomsetCatalogDialog.kt`
  `ProviderHeader` (L90–102) shows provider name, licence text, homepage, provenance, the date
  listings were checked and, for Homebrew Hub, `providers35_hh_terms`. The game page names only
  the metadata source (`details_source`, `ui/screens/game/GamePage.kt` L693) — not the catalogue
  provider, and the non-commercial terms are not shown before a download.
- Source health is *now*, not *over time*: `data/state/SourceScanResults.kt` keeps one row per
  `console|url` (`data/service/SourceScanService.kt` `record()` L197–217),
  `util/SourceHealth.kt` maps that last row to OK/PARTIAL/FAILED, and
  `util/SourceRanking.kt` (`files/source_track.json`) halves its success/failure counts above 100
  so time falls away. Failure kinds and backoff already exist in `util/ScanFailures.kt`.
- An arcade console is closer than it looks: `PlaySystem.ARCADE` (L59) with cores
  `fbneo`/`mame2003_plus`/`mamearcade`, `TargetFolderLayouts.System.ARCADE` and `FBNEO`
  (L137–138, L243, and ArkOS shares `arcade` with FBNEO at L266) exist, and
  `TargetFolderLayoutsTest` (L86, L93) already requires `arcade_mame` to map. Missing: rows in
  `util/ConsoleFolderAliases.kt` and `util/ConsoleFormatter.kt` (labels), cover tables in
  `util/LibretroThumbnails.kt` / `util/Igdb.kt` / `util/ScreenScraper.kt` / `util/TheGamesDb.kt`,
  and per-board MAME BIOS (`util/BiosCatalog.kt` knows only `neogeo.zip`, L94–95).

## 1. Source history: see a failing source before it fails again

**Why.** `SourceScanResults` stores only the last outcome, so a source that has failed three
Mondays in a row looks exactly like one that failed once.

**What.** A small bounded history per source (say 12 outcomes: when, result, failure kind) written
atomically with the existing row, a pure `util/SourceHealth.trend()` turning it into one sentence
("failed 3 times this month, last: rate limited"), and one line under the last-scan status in
`ui/screens/sources/components/ConsoleCard.kt` (`UrlItem` L352–433), with the ScanReport dialog
offering the same retry it already offers.

**Files.** `data/state/SourceScanResults.kt`, `data/service/SourceScanService.kt` (`record()`),
`util/SourceHealth.kt`, `util/ScanFailures.kt`, `ui/screens/sources/components/ConsoleCard.kt`,
`ui/screens/sources/components/ScanReport.kt`, `util/HealthRules.kt` (L31–41), new
`app/src/test/java/com/tufein/valkyr/util/SourceHealthTrendTest.kt`,
`app/src/main/res/values/strings_v78_sources.xml` plus the six locale copies.

**Done when.** The trend function is tested on synthetic outcome lists (rate limited, moved host,
intermittent, healthy) and a demoted download source and a failing scan source are told apart in
one sentence each.

## 2. Mirrors and background scans for catalogue sources

**Why.** Catalogue entries are added without mirrors while the app already has a mirror mechanism,
and background scans already skip unchanged listings.

**What.** `mirrors` in `romsets.json` entries, reviewed as part of `TRUSTED`, handed to `UrlEntry`
in `mergeRomsets()`, and the reserve-address behaviour applied to the catalogue scan path too.
Changing parsing means raising `ListingCheck.PARSER_VERSION` (or `HomebrewHub.PARSER_VERSION`),
which forces one full re-read — say so in the release notes.

**Files.** `app/src/main/assets/romsets.json`, `util/RomsetCatalog.kt`,
`data/repository/SourcesRepository.kt`, `data/service/DatabaseScrapingService.kt`,
`util/ListingCheck.kt`, `data/service/AutoScanScheduler.kt`, `util/AutoScanPolicy.kt`,
`RomsetCatalogTest` (counts), `SourcesJsonTest`.

**Done when.** A catalogue entry with a mirror is served from the mirror when the main address
fails, and an unchanged catalogue scan writes nothing.

## 3. Provider named wherever its content is shown

**Why.** The provider is decided and displayed in the browser dialog, then disappears.

**What.** Derive the provider from `file.sourceUrl` through `RomsetCatalog` /
`HomebrewHub.platformOf` and show one line on the game page beside the metadata source, plus the
licence terms **before** the first download of a catalogue item, not only in the dialog.

**Files.** `ui/screens/home/GameDetailsLoader.kt`, `ui/screens/game/GamePage.kt`,
`ui/screens/download/` (the download dialog), `util/RomsetCatalog.kt`, `util/HomebrewHub.kt`,
`app/src/main/res/values/strings_v35_providers.xml` (extended) and `strings_v78_sources.xml`.

**Done when.** Every catalogue game names its provider on its page, and a download of a
non-commercial-licence item shows the terms with a way to cancel.

## 4. More Homebrew Hub systems

**Why.** The reader is one platform deep while the API is not.

**What.** New `Platform` entries with their base path and extensions, new asset entries, and the
same licence whitelist rules. Each addition is a review of that catalogue's terms, not a code
problem.

**Files.** `util/HomebrewHub.kt`, `app/src/main/assets/romsets.json`,
`data/service/DatabaseScrapingService.kt` (`scrapeHomebrewHub` L204–235),
`app/src/test/resources/homebrewhub/*.json` fixtures, `HomebrewHubTest`, `RomsetCatalogTest`.

**Done when.** Fixtures cover the new platform's page shape and licence column, and the entry maps
to an existing console id that `TargetFolderLayoutsTest` accepts.

## 5. MAME's free-to-download content, only when it is honest

**Why.** The roadmap keeps this as a candidate, and the conditions are specific: an arcade console
in the app, and the non-commercial terms shown to the user before downloading. Neither exists yet.

**What.** A fourth `Licence` with its own text and a gate before download, an arcade console id
(`arcade_mame`, already expected by `TargetFolderLayoutsTest` L86) with rows in
`ConsoleFolderAliases`, `ConsoleFormatter`, cover tables and a note about per-board BIOS, and a
catalogue reader for the free-to-download sets. The size caps rule the shape: `MAX_FOLDERS = 16`
and `MAX_ENTRIES = 256` mean this cannot be one entry with hundreds of folders — either many
entries, or a new `Kind` reader like the Homebrew Hub one. Complete commercial sets stay out:
this project does not point at sources that exist to distribute them.

**Files.** `util/RomsetCatalog.kt` (`Licence`, `Kind`, caps), `util/ConsoleFolderAliases.kt`,
`util/ConsoleFormatter.kt`, `util/ConsoleFamily.kt`, `util/LibretroThumbnails.kt`,
`util/Igdb.kt`, `util/ScreenScraper.kt`, `util/TheGamesDb.kt`, `util/BiosCatalog.kt`,
`util/EmulatorCatalog.kt` (already has `ARCADE`), new `util/MameCatalogue.kt`,
`data/service/DatabaseScrapingService.kt`, `app/src/main/assets/romsets.json`,
`TargetFolderLayoutsTest`, `RomsetCatalogTest`, `ConsoleFolderAliasesTest`, plus the release note
that says plainly what this catalogue does and does not contain.

**Done when.** Terms are shown before the first download and declined means nothing is fetched;
the console appears with covers or an honest "no art for this system yet"; and the entry count,
file counts and folder names pass the two asset gates.

## Order of work

1 is the thing users ask for and needs no new provider. 2 and 3 are small and make the catalogue
behave like the rest of the app. 4 is content review plus a fixture. 5 is the only one that adds a
console, and it goes last because 7.4 (BIOS and cores) makes it usable.

## Where this runs

Everything except the real scans is pure-JVM tested with fixtures. Tickets 2, 4 and 5 end with a
scan of the live catalogue on a device — a listing that parses in a test but 410s on a handheld is
not done.
